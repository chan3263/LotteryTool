# 算法原理与验证细节

本文是 [README](../README.md) 中「算法原理」章节的展开，面向想理解或修改引擎的读者。

> **前提**：大乐透每期开奖是独立、均匀的随机事件。本文描述的所有方法只改变「按什么分布生成号码」，**不改变期望中奖率**。任何声称能从历史数据中提取预测信息的做法，在数学上都不成立。

---

## 1. 符号约定与概率尺度

这是最容易误解的地方，务必区分两个尺度：

| 量 | 定义 | 前区 | 后区 |
|---|---|---|---|
| `u_i` | 均匀基准的抽样概率 | `1/35` | `1/12` |
| `p_i` | 平滑后的归一化抽样概率，`Σ p_i = 1` | — | — |
| 每期出现率 | 号码在单期中出现的概率 | `5 · p_i`，均匀时 `5/35` | `2 · p_i`，均匀时 `2/12` |

`FrontProb` / `BackProb` 存的是**归一化抽样概率**（和为 1），不是「每期出现率」。UI 展示用 `AppearanceRate` 换算成出现率；`Lift = p_i / u_i` 在两种尺度下比值相同。

---

## 2. 数据预处理与时间衰减

窗口取最近 `W = min(N, 总期数)` 期。第 `k` 期（从最新往回数，`age = 0` 为最新）的权重：

```
w_k ∝ 0.5^(age / halfLife)
halfLife = N / 3        // RecencyHalfLife = 0 时自动取此值
```

`w_k` 归一化后用于加权计数。相比 v2.0 的「硬截断取最近 N 期」：

- 窗口内所有期都贡献信息，避免边界处权重从 1 突降到 0
- 近期信息更突出，长期样本仍保留
- `N > 数据量` 时取 `min(N, Count)`，不会像 v2.0 那样静默退化成均匀随机

令 `c_i = Σ_k w_k · 1[号码 i 出现于第 k 期]`，则 `Σ_i c_i` 等于每期号码数（前区 5、后区 2）。

---

## 3. Dirichlet 平滑的边际概率

取均匀先验 `u_i`，伪计数强度 `α = 20`：

```
p_i = (c_i + α · u_i) / (5 + α)     // 前区，Σ p_i = 1
p_i = (c_i + α · u_i) / (2 + α)     // 后区，Σ p_i = 1
```

这等价于对多项分布参数做 Dirichlet 后验均值估计。强平滑是刻意的：100 期窗口里单个号码的出现次数期望约 14 次，标准差约 3.5，频率波动几乎不含可预测信息；不收缩只会把噪声当信号。验证时要求 `Σ p_i = 1.00000000`。

---

## 4. 共现收缩估计

`W` 期窗口内，任意两个特定前区号码共同出现的期望次数约为：

```
W · C(5,2) / C(35,2) = W · 10 / 595 ≈ W / 59.5
```

`W = 100` 时期望仅约 **1.68 次**，`W = 50` 时不足 1 次。直接计算 `co(A,B) / count(B)` 得到的几乎全是 0/1 噪声。v3.0 用伪计数 `β = 25` 把条件概率收缩回边际：

```
P(A|B) = (co(A,B) + β · p_A) / (c_B + β)
lift(A,B) = P(A|B) / p_A          // 裁剪到 [0.25, 4]
```

`lift` **只用于组合评分**，不再像 v2.0 那样连乘放大抽样概率。这是修复 v2.0 `∏(1+likelihood)` 伪贝叶斯连乘的关键——那个式子不是贝叶斯公式，且会被稀疏共现噪声主导。

---

## 5. Gumbel-top-k 无放回加权抽样

旧版逐个轮盘赌、每选一个号码就手工改写概率，既非标准模型又慢。v3.0 使用指数竞赛（Gumbel-top-k）：

```
对每个号码 i：E_i ~ Exp(1)，key_i = E_i / w_i
取 key 最小的 k 个作为选中号码
```

**数学等价性**：`E_i ~ Exp(1)` 时 `E_i / w_i` 服从 `Exp(w_i)`，最小值出现在 `i` 的概率为 `w_i / Σw`；取走后由指数分布的无记忆性，剩余竞次仍服从同一族分布。因此这**严格等价于 Plackett-Luce 依次无放回抽样**，但一次 `O(n log n)` 生成整注（前区 35 选 5、后区 12 选 2），无需逐次重归一化，也没有「手工改概率」带来的分布偏差。

---

## 6. 策略权重

权重与统计量**解耦**：`ComputeStats` 只描述历史数据，`BuildWeightVectors(s, opt, out fw, out bw)` 按本次调用的策略显式构建权重并传入 `GenerateOne`。若把权重塞回 `ModelStats`，`Predict(count, opt)` 传入的策略将不会生效（这是开发过程中实际踩过的坑）。

| 策略 | 权重信号 | 公式 |
|---|---|---|
| Uniform | 全 1（与真实开奖机制一致，对照基准） | `w_i = 1` |
| Hot | 窗口内实际出现频率 `freq_i` | `freq_i^(2γ)` |
| Cold | 当前遗漏 / 平均间隔 | `(1 + omission_i / interval_i)^γ` |
| Balanced | 平滑后边际概率 | `(p_i / u_i)^(γ/2)` |

`γ = WeightStrength ∈ [0, 2]`，默认 1.0，0 等价于均匀随机。权重裁剪到 `[0.2, 5]` 避免极端偏态。不同策略使用**独立随机流**（固定种子 + 策略偏移），保证策略间结果可区分且各自可复现。

---

## 7. 结构约束

| 约束 | 默认范围 | 说明 |
|---|---|---|
| 前区和值 | 55 ~ 130 | 理论均值 90、标准差约 22.6 |
| 后区和值 | 5 ~ 21 | 理论均值 13 |
| 奇数 / 大号(≥18) 个数 | 各 1 ~ 4 | 排除全奇、全偶、全大、全小 |
| 连号对数 | ≤ 2 | 如 `08 09` 记 1 对 |
| AC 值 | ≥ 3 | 两两差的不同值个数 − (n−1) |
| 与上期前区重复 | ≤ 3 | 避免与上期高度雷同 |

采用**拒绝采样**：生成候选 → 校验 → 不合格则重试，超过 `MaxAttemptsPerCombination = 200` 时软降级并计数，保证不死循环。

> 这些约束只是过滤现实中极罕见的组合形态。**在均匀随机开奖下，被过滤掉的组合与保留的组合中奖概率完全相同。**

---

## 8. 可解释评分

```
score = 50 + 32 · tanh(2.5 · (0.6 · 平均对数似然提升 + 0.4 · 平均 log(lift))) + 结构修正
```

- 50 分 ≈ 与均匀随机基准相当
- 分数只表示「像不像历史统计特征」，**不是中奖置信度**
- v2.0 把平均边缘概率标为「置信度」，极易被误读成中奖率，v3.0 已更名并加注

## 9. Walk-forward 回测

对第 `t` 期：

1. 只用 `data[0..t)` 训练（**无未来信息泄漏**）
2. 按当前策略生成 `betsPerDraw` 注，与真实开奖比对
3. 对照组为**施加相同结构过滤**的均匀随机选号，保证比较公平
4. 汇总平均命中数、命中分布、一等奖次数

理论期望（与所选号码无关）：

```
前区：5 注号码 × 5 个中奖号 / 35 = 25/35 ≈ 0.7143
后区：2 注号码 × 2 个中奖号 / 12 =  4/12 ≈ 0.3333
总计：≈ 1.0476
```

最少需要 **31 期**数据（`MinTrain = 30`）。回测报告必须包含模型、随机基准、理论期望三列对照，并如实写明「无显著差异」。

### 一次实测（2738 期，N=100，200 期 × 20 注 = 4000 注）

| 指标 | 模型策略 | 随机基准 | 理论期望 |
|---|---|---|---|
| 前区平均命中 | 0.7145 | 0.7047 | 0.7143 |
| 后区平均命中 | 0.3245 | 0.3257 | 0.3333 |
| 总平均命中 | 1.0390 | 1.0305 | 1.0476 |
| 一等奖 (5+2) | 0 次 | 0 次 | — |

前区平均命中差 +0.0098 个/注，属于抽样波动。每次运行因随机基准与种子不同略有浮动，但始终围绕理论期望。

## 10. 工程实现要点

- **惰性计算 + 脏标记**：`TrainModel` / `SetNPeriods` / `SetOptions` 只打脏标记，统计量在 `EnsureStats()` 首次使用时计算，避免重复点击预测时反复训练
- **权重与统计量解耦**：见第 6 节
- **随机源语义**：固定种子 → 每次生成从 `seed + 策略偏移` 重新开始（可复现）；未指定 → 复用同一条随机流（连续点击结果不同）
- **组合去重**：`HashSet<string>` 存 `CombinationKey`，大批量生成时跳过重复组合
- **性能**：二维数组预计算替代字符串字典查共现、全表 LINQ 扫描

## 11. v2.0 缺陷与 v3.0 修复对照

| 问题 | v2.0 | v3.0 |
|---|---|---|
| 随机源 | 每次轮盘赌 `new Random(Guid...)`,种子相关且极慢 | 单一 `Random` 实例，固定种子与策略独立流 |
| 先验归一化 | 前区总和为 5 却按 1 归一 | Dirichlet 平滑，概率严格和为 1 |
| 贝叶斯更新 | `∏(1 + likelihood·prior)` 连乘，非贝叶斯公式 | 收缩估计的 `lift`，仅用于评分 |
| 二阶共现 | 50 期直接估 `P(A\|B)`，几乎纯噪声 | β 伪计数收缩回边际 |
| `N > 数据量` | `if (Count < nPeriods) return`，静默退化 | `min(N, Count)` 始终有效 |
| 后区选号 | 依赖更新只在前区执行 | 前后区统一处理 |
| 抽样方式 | 逐次轮盘赌 + 手工改概率 | Gumbel-top-k 指数竞赛 |
| 组合结构 | 无约束、无去重 | 结构过滤 + 组合去重 + 软降级 |
| 置信度 | 平均边缘概率，易误解为中奖率 | 明确标注「贴合度 0~100」 |
| 数据层 | 不校验、不去重、日期格式单一 | 多格式解析、逐行容错、按期号去重 |
| 效果验证 | 无 | Walk-forward 回测 + 随机基准对照 |

## 12. 验证清单

不要用 GUI 手工验证算法。建议建临时控制台项目，直接引用 `Models/*.cs` 与 `Services/*.cs` 跑真实数据回归，至少覆盖：

- [ ] 前区 / 后区概率和为 1（打印到 8 位小数）
- [ ] 号码合法性：范围、不重复、升序，前后区数量正确
- [ ] 大批量生成（≥ 20000 注）的性能、全部唯一、结构约束 100% 满足
- [ ] 固定种子两次生成结果完全一致
- [ ] 不同策略结果确实不同（两两重合数为 0）
- [ ] **策略倾向性**：不能只检查「随机流不同」，要统计各策略生成号码的平均窗口出现次数 / 平均遗漏，确认权重真的产生偏向
- [ ] 回测命中数与理论期望对照，结论写明「无显著差异」
- [ ] 导出 → 再导入往返一致（含中文期号）

参考实测：20000 注约 146 ms 且全部唯一，200 期 × 20 注回测约 87 ms；策略倾向性上热号平均窗口出现 15.63 次（基准 14.23）、冷号平均遗漏 11.27 期（基准 6.83）。
